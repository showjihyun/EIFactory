관점: **보안과 위험 등급**

1. 인증·인가 우회, 토큰·세션 처리 오류가 없는가.
2. 사용자 입력 검증이 빠지지 않았는가 (URL, 태그, 검색어). SQL은 매개변수로 넘기는가.
3. 비밀정보(키, 비밀번호, 토큰)를 코드·로그·응답에 남기지 않는가.
4. 데이터 삭제·스키마 변경처럼 되돌리기 어려운 변경이 있는가.
5. contract의 위험 등급(`risk`)이 실제 변경보다 낮게 선언되지 않았는가. 낮다고 보면 FAIL로 하지 말고 `risk_up`으로 올릴 등급과 근거를 적는다 (구현을 다시 해도 등급 문제는 풀리지 않는다. 올린 등급은 사람 승인으로 간다).
