관점: **요구사항 충족과 범위**

1. diff가 요구사항과 contract의 `acceptance_criteria`를 실제로 충족하는가. 수락 테스트가 통과했다는 사실만으로 충분하다고 보지 않는다.
2. 요구사항과 관계없는 변경(리팩터링, 이름 변경, 기능 추가)이 섞여 있지 않은가.
3. 명백한 버그(경계값, 빈 값, 오류 처리 누락, 화면 상태 누락)가 없는가.
4. refactor 유형이면 동작이 바뀌지 않았는가.
5. 화면 변경이면 레포 루트 `DESIGN.md`를 따르는가: 정의된 토큰·컴포넌트만 쓰는지, 임의 색·간격·인라인 style을 새로 넣지 않았는지, 정한 상태(빈 목록, 로딩, 오류)를 보여 주는지.
